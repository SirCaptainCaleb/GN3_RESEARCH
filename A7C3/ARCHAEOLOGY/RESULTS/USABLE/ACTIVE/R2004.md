# R2004 — Source-predecessor coincidence reduces to one seam or one reverse trimer

**Status:** PASS
**Source:** workspace root `1789411244.407239`

## Statement

Let `c=b_{t+1}` be the first R1033-open spectator in the later non-loop OUT-`v` pre-loss state `M=hat M_{r-1}`. Suppose the selected predecessor of `c` is the far source spoke `s`, so `s->c` is selected while `s,in` is the fixed free copy.

Then `s` is the source of that rail, and the old closure

`M+{v->s}`

has exact two-cover matching cardinality, is acyclic, and has transition count `1`. Its only new turn is

`(v,s,c)`.

Therefore either this turn is tight and the closure is a literal tight two-path cover of the current `G` support, or R3 forces the reverse tight trimer

`(c,s,v)`.

## Proof

Because `s,in` is unmatched in M, the physical vertex s has no selected predecessor. Since `s->c` is selected, s is the first vertex of its path component, which therefore begins

`s -> c -> ...`.

By R1060, v is an isolated singleton component of M. Adding `v->s` joins that singleton to the s-starting rail. Hence matching cardinality rises by one to the exact two-cover cardinality, no directed cycle is created, and there is no new turn at v.

At s, the selected successor is c, so the only new turn is `(v,s,c)`. The closure edge `v->s` is X-X. The preceding normalized closure in the first-loss packet has transition count one by R1036, so

`tau(M+{v->s})=1`.

If `(v,s,c)` is tight, every turn of the resulting selected graph is tight and the two components form a literal tight two-path cover of the G-support.

If `(v,s,c)` is bad, the vertices v,s,c are pairwise distinct: `v!=s` in the non-loop branch and `c∈B` while `v,s∈X`. R3 therefore gives the reverse tight trimer `(c,s,v)`.
